# 第2章 第4節: フォールバック機能付きLLMクライアント

この節では、フォールバック機能、リトライメカニズム、包括的なエラーハンドリングを備えた堅牢なLLMクライアントの実装方法を説明します。

## 概要

このアプリケーションは以下の機能を示しています：
- **フォールバック戦略**: プライマリとセカンダリのLLMプロバイダー（OpenAI → Google Gemini）
- **設定可能なリトライロジック**: 指数バックオフ、ジッター、タイムアウト制御
- **構造化された出力**: Pydanticモデルを使用した型安全なレスポンス
- **エラーハンドリング**: プライマリプロバイダーが失敗した際のグレースフルフォールバック

## 機能

### フォールバック機能付きLLMクライアント
- プライマリクライアント: OpenAI GPT-4o-mini
- フォールバッククライアント: Google Gemini 2.5 Flash
- プライマリクライアントでエラーが発生した際の自動フェイルオーバー

### リトライメカニズム
- 設定可能なタイムアウト（デフォルト: 10秒）
- 最大リトライ回数（デフォルト: 3回）
- カスタマイズ可能な係数による指数バックオフ
- サンダリングハード問題を防ぐためのジッター
- 最大バックオフ時間の制限

### キャラクター生成
- 構造化されたデータによる架空のキャラクター生成
- 名前、性別、年齢、性格特性を含む
- Pydanticモデルを使用した出力検証
- JSONファイルとして結果を保存

## 使用方法

```bash
# 基本的な使用方法
python src/main.py

# カスタムリトライ設定
python src/main.py --timeout 15 --max-retries 5

# 指数バックオフを有効にする
python src/main.py --exponential-backoff --backoff-factor 1.5

# ジッターを有効にする
python src/main.py --exponential-backoff --jitter
```

## コマンドラインオプション

- `--timeout, -t`: リクエストタイムアウト（秒）（デフォルト: 10）
- `--max-retries, -r`: 最大リトライ回数（デフォルト: 3）
- `--exponential-backoff, -eb`: 指数バックオフを有効にする
- `--backoff-factor, -bf`: 指数バックオフの乗数（デフォルト: 2.0）
- `--max-backoff, -mb`: 最大バックオフ時間（秒）（デフォルト: 60）
- `--jitter, -j`: バックオフタイミングにランダム化を追加

## 設定

`.env`ファイルでAPIキーを設定してください：

```env
OPENAI_API_KEY=your_openai_api_key_here
GEMINI_API_KEY=your_gemini_api_key_here
```

## アーキテクチャ

### 主要コンポーネント

- **LLMClientWithFallback**: プライマリ/フォールバックロジックを統制するメインクライアント
- **LLMRequestRetryOptions**: リトライ動作の設定
- **CharacterResponse**: 構造化された出力のためのPydanticモデル
- **FailedResponse**: エラーハンドリングモデル

### フロー

1. CLIパラメータからリトライオプションを設定
2. プライマリ（OpenAI）とセカンダリ（Gemini）プロバイダーでフォールバッククライアントを作成
3. キャラクタープロンプトを生成
4. プライマリクライアントでリクエストを試行
5. 失敗時、フォールバッククライアントで自動的にリトライ
6. 成功したレスポンスをJSONファイルとして保存

## エラーハンドリング

このアプリケーションは様々な失敗シナリオを処理します：
- ネットワークタイムアウトと接続エラー
- APIレート制限
- サービス利用不可
- 無効なAPIレスポンス
- 認証失敗

両方のプロバイダーですべてのリトライ試行が失敗した場合、詳細なエラー情報がログに記録され、返されます。
